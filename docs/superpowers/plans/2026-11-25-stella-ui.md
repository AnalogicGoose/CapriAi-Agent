# Stella UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle every Capri overlay and the control room in Stella's "Orbit" look, render formatted chat text with safe clickable links, rebuild the control room as one compact folding page, and switch the visible name and wake word to Stella.

**Architecture:** One shared `stella-theme.css` (tokens + primitives) is loaded by every renderer page; overlays keep their DOM ids and JS and are restyled in place. A new DOM-only `rich-text.js` formats model text; links go through a new validated `link:open` IPC to the existing preferred-browser opener. The control room is drawn by a small renderer from a declarative `settings-schema.js`; the main-process settings policy is unchanged.

**Tech Stack:** Electron (sandboxed, contextIsolation), vanilla ES modules (renderer), CommonJS (main), CSS, `node --test`, `electron scripts/smoke-electron.js`.

**Spec:** `docs/superpowers/specs/2026-11-25-stella-ui-design.md` (read it first; mockups in `.superpowers/brainstorm/1307-1795634298/content/style-direction.html` (card C) and `control-room-layout-v2.html` (card A)).

## Global Constraints

- Branch `feature/stella-ui` from `feature/stella-character` (project 1 is not merged). Never push or merge without the owner asking.
- No build step, no framework, no new npm dependencies, no web fonts. CSP stays as is (`script-src 'self'; style-src 'self'`): no inline `<script>` or `style=""` attributes generated at runtime except `el.style.setProperty` from JS.
- Fonts: `"Segoe UI Variable", "Segoe UI", system-ui` for text; bundled JetBrains Mono only for inline code. Chakra Petch is not used on any screen in this project.
- Palette tokens (exact): bg `#08071c` → `#1d1850`; panel fill `rgba(36,30,86,.92)` → `rgba(16,14,44,.94)`; text `#ece9ff`; muted `#a9a3d6` / `#8f89c0`; lavender `#b9a4f5`; violet `#8b5cf6`; blue `#5b8cff`; link `#7ea6ff`; gold `#f6dc9c`; rose `#f2b8c6`; warm white `#fff1d6`; ok `#8ee6b0`. Hairline: `linear-gradient(120deg, rgba(246,220,156,.7), rgba(242,184,198,.45) 30%, rgba(139,92,246,.25) 60%, rgba(91,140,255,.5))` via masked pseudo-element.
- Radii: pills `999px`, panels/windows `22–24px`, tiles `16px`. Icon buttons are circles of exactly 30 / 34 / 46 px, `display:grid; place-items:center`, SVG `display:block`, 24-unit viewBox; unbalanced icons get an optical offset class verified by screenshot.
- `prefers-reduced-motion`: no sheen/flicker, instant section folds.
- Never set model text with `innerHTML`. Only `https:` links that pass `publicUrl()` (`src/main/web-tools.js`) are clickable.
- Do not change `settings-policy.js` accepted keys, settings/config storage paths, `app.setName('Capri')`, the `CapriGPT` appData folder, code identifiers, file names, CSS class prefixes, icons or the repo (project 3).
- Visible name text = `DISPLAY_NAME` (`'Stella'`). Wording drops "choom", "digital ghost", "biochip", "your space / your rules", "Make yourself at home".

## Review Focus

1. **Half-typed formatting during the decode animation** (`**bol` mid-reveal): the user must never see raw `**`/backticks flash; final text is formatted. → Task 4 test `decode never shows raw markers`.
2. **Model text containing HTML** (`<img src=x onerror=alert(1)>`, `<a href="javascript:…">`): shows literally as text, no element created. → Task 2 test `html in text stays text`.
3. **URL followed by punctuation or inside parentheses** (`(see https://a.com/x).`): link is `https://a.com/x`, the `).` stays text. → Task 2 test `bare url trims trailing punctuation`.
4. **Control room while gaming mode is on**: Gaming tile and Quit stay visible and clickable; status says she's taking a break. → Task 8 test `gaming pause keeps resume and quit`.
5. **Link that can't open** (http, IP host, preferred browser missing): nothing navigates the overlay; a one-line note appears in the panel. → Task 3 test `rejected urls return error` + Task 4 test `failed link shows note`.

### Task 2: Rich text formatter

**Files:**
- Create: `src/renderer/js/rich-text.js`
- Test: `tests/rich-text.test.js` (import via `data:` URI like `tests/settings-ui.test.js`)

**Interfaces:**
- Produces (ES module):
  - `parseRichText(text: string): Block[]` where `Block = { type: 'p', inlines: Inline[] } | { type: 'ul', items: Inline[][] }` and `Inline = { type: 'text'|'b'|'i'|'code', text: string } | { type: 'link', text: string, href: string }`. Paragraphs split on blank lines; single newlines inside a paragraph become `{ type: 'text', text: '\n' }`. Consecutive lines starting `- ` or `* ` form one `ul`.
  - `renderRichText(node: Element, text: string, { onLink?: (href: string) => void } = {}): void`: clears `node`, appends `<p>`, `<ul><li>`, `<strong>`, `<em>`, `<code>`, `<a href class="rich-link">`, `<br>`, using only `node.ownerDocument.createElement` / `createTextNode`. Link click → `event.preventDefault(); onLink?.(href)`.
  - `plainText(text: string): string`: same parse, markers removed, links as their label (or URL), list items as `- item` lines. Used for TTS and the decode animation.
- Link rules: `[label](url)` and bare `https?://…`; href must parse with `new URL` and have protocol `https:`, else the whole thing renders as plain text (label for `[label](url)`, raw text for bare). Bare URLs end before whitespace and exclude trailing `.,;:!?)]}'"` unless the `)` closes a `(` inside the URL.

- [ ] **Step 1: Write failing tests** (assert on `parseRichText` output unless stated):
  - `bold italic code`: `'a **b** *c* _d_ `e`'` → inlines `text a`, `b b`, `text  `, `i c`, `text  `, `i d`, `text  `, `code e`.
  - `unmatched markers stay literal`: `'2 * 3 and **open'` → single `text` inline equal to the input.
  - `markdown link`: `'[Recipe](https://seriouseats.com/x)'` → `{type:'link', text:'Recipe', href:'https://seriouseats.com/x'}`.
  - `bare url trims trailing punctuation`: `'(see https://a.com/x).'` → link href `https://a.com/x`; text after is `').'`. Also `'https://en.wikipedia.org/wiki/Foo_(bar).'` keeps `(bar)` in the href.
  - `non-https links are text`: `'[x](javascript:alert(1))'`, `'http://a.com'`, `'[f](file:///C:/x)'` → no `link` inline anywhere.
